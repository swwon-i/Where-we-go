## 0. 먼저 — 세 방식이 같은 답을 내는가

출발지 5곳 × 후보 20곳 = 100 쌍에서 세 방식의 소요시간이 모두 같다. 아래 시간은 **같은 답을 내는 세 방식**의 비교다.

## 1. 휴리스틱은 얼마나 센가

A* 의 이득은 전부 휴리스틱에서 나온다. `h(n) = 직선거리 / 최고속도` 가 실제 소요시간의 몇 할인지 재면 A* 가 얼마나 치우칠 수 있는지가 먼저 보인다.

| 항목 | 값 |
|---|---|
| 관측 최고 속도 (휴리스틱의 분모) | 25.5 m/s · 92 km/h |
| `h / 실제 소요시간` 중앙값 | **12.2%** |
| `h / 실제` p95 | 17.6% |
| 표본 | 출발지 30곳 × 후보 20곳 |

휴리스틱이 실제 비용의 작은 몫만 설명한다. 분모가 **급행 지하철 속도**인데 실제 이동은 도보·대기·환승이 섞여 있어서다 — 직선거리로는 설명되지 않는 비용이 대부분이고, 그만큼 A* 는 목표 쪽으로 치우치지 못한다. 허용 휴리스틱을 유지하려면 분모를 더 낮출 수 없다(낮추면 답이 틀린다).

## 3. 후보 20곳 — 행렬 한 줄의 실제 모양

행렬(`POST /rooms/{id}/matrix`)은 사람마다 후보 전부까지의 시간을 한 줄로 낸다. A* 는 목표가 여러 곳이면 치우칠 방향이 없으므로 **후보마다 따로** 돌려야 한다.

| 후보 위치 | 방식 | 탐색 횟수 | 중앙값 | p95 | 확정 노드(중앙값) |
|---|---|---|---|---|---|
| 한 동네(반경 1km) | 다익스트라 one-to-many (지금) | 1회 | 27.5 ms | 221.0 ms | 91,260 |
| | 다익스트라 1:1 × 20 | 20회 | 1458.3 ms | 2208.1 ms | 1,496,072 |
| | **A\* 1:1 × 20** | 20회 | 1226.4 ms | 1954.3 ms | 1,014,651 |
| | A\* 가 one-to-many 대비 | | **44.52×** | | 11.12× |
| 서울 전역 | 다익스트라 one-to-many (지금) | 1회 | 233.2 ms | 255.0 ms | 192,697 |
| | 다익스트라 1:1 × 20 | 20회 | 2037.8 ms | 2714.0 ms | 2,101,597 |
| | **A\* 1:1 × 20** | 20회 | 2014.6 ms | 2468.5 ms | 1,577,615 |
| | A\* 가 one-to-many 대비 | | **8.64×** | | 8.19× |

`확정 노드` 는 탐색이 꺼낸 노드 수의 합이다. one-to-many 가 1회로 끝내는 일을 1:1 은 20 번 되풀이하면서 **출발지 근처를 매번 다시 확정한다** — A* 가 한 번당 아끼는 몫보다 그 중복이 크다.
